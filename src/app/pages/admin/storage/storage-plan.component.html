RAID group capacity

column H

A RAID group gives up whole disks to parity, and those disks hold no video: usable = total − parity, then capacity = disk size × usable × 0.90. The workbook applies this in the main table but not in the ANPR one.

The parity defect

sheet1 H37:H40 · sheet2 H35:H38

The ANPR table computes F × E × 90%, where F is total disks including parity. The parity disk is counted as usable space.

The one number that moves. Across the array the overstatement is 208.8 → 180.0 TB — a gap of 28.8 TB, which is exactly the four parity disks being counted as usable space. What building it would take

This page documents the model. Turning it into a working tool is a calculator screen here in the admin panel, backed by a stateless POST /api/storage-designs/calculate in jamago-api that follows the existing CQRS layout and reuses TypedResult<T> — no new infrastructure, no entity and no migration, so nothing touches the shared database.

The tests are already written down: 327.53 TB and 250 Mbps for the Dahua fixture, 28.8 TB and a ceiling of 9 for the RAID-5 group, 72.0 TB and 23 for RAID-6, 6.95 TB of failover, 0.78231 TB per ANPR camera — and 43.2 TB, not 50.4, for the ANPR group, which is the one assertion that deliberately disagrees with the workbook.
